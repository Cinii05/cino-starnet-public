# cino-skill-governor

## Classification
1. Define the repeated problem and recurrence evidence.
2. Check existing skill/rule/script/router/automation/memory/docs before creating anything.
3. Put judgment/procedure in a skill; short invariant in a rule/router; deterministic transformation/check in a script; scheduled/event integration in automation; fact/preference in memory; governing project truth in canonical docs.
4. Prefer extending an umbrella over a duplicate micro-skill. Do not create a skill for a one-line deterministic chore.
5. Preserve unique authority, recovery, failure and evidence behavior before any consolidation/archive.

## Lifecycle
Classification-only work stops before mutation. When install/update/promotion/rollback/retirement is material, load cino-skill-governor-approval-model.

Skill management never enlarges execution/deployment authority. Record provenance/version and preserve rollback.
